# Webby Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a runnable, tested Phoenix foundation for Webby with SQLite persistence, loopback-only service configuration, an atomic runtime discovery file, and a local status surface.

**Architecture:** A Phoenix 1.8 application runs as the single supervised Webby authority. `Webby.Paths` resolves platform state locations, `Webby.RuntimeDiscovery` atomically publishes non-secret process metadata, and `WebbyWeb.StatusController` plus a LiveView dashboard expose local health without coupling later MCP or browser components to web adapters.

**Tech Stack:** Elixir 1.20.3 / OTP 29.0.5, Phoenix 1.8.11 generated with `phx_new` 1.8.9, Phoenix LiveView 1.2.9, Ecto SQL, `ecto_sqlite3` 0.24.1, Bandit 1.12.4, ExUnit, mise.

**Spec:** `docs/superpowers/specs/2026-08-13-webby-design.md`

## Global Constraints

- Product, OTP application, root module, and MCP server identity are exactly `Webby`, `webby`, `Webby`, and `webby`.
- Default listener is exactly `127.0.0.1:6477`; binding another interface requires an explicit future design and is not implemented here.
- SQLite is authoritative durable storage and runs in WAL mode.
- Runtime metadata is written atomically, owner-only, contains no credentials, and follows platform application-data conventions.
- Webby must not depend on Labby packages, configuration, credentials, processes, APIs, or endpoints.
- Application code uses supervised processes and structured Logger metadata; it does not use ad-hoc background tasks.
- Each task ends with focused tests and a commit; no later task may bypass an interface produced by an earlier task.

- [ ] **Step 3: Implement deterministic platform paths**

Create `Webby.Paths` with public zero-argument functions and private OS-specific roots. Linux uses `XDG_CONFIG_HOME`, `XDG_DATA_HOME`, and `XDG_STATE_HOME`, falling back to `~/.config`, `~/.local/share`, and `~/.local/state`. macOS uses `~/Library/Application Support/Webby` and `~/Library/Logs/Webby`. - [ ] **Step 4: Write failing runtime-discovery tests**

Create `test/webby/runtime_discovery_test.exs` that starts the process with an injected path and fixed metadata provider:

```elixir
start_supervised!({Webby.RuntimeDiscovery,
  path: runtime_path,
  metadata: fn ->
    %{instance_id: "instance-1", base_url: "http://127.0.0.1:6477",
      mcp_url: "http://127.0.0.1:6477/mcp", pid: 1234}
  end})

assert Jason.decode!(File.read!(runtime_path)) == %{
  "instance_id" => "instance-1",
  "base_url" => "http://127.0.0.1:6477",
  "mcp_url" => "http://127.0.0.1:6477/mcp",
  "pid" => 1234
}
assert File.stat!(runtime_path).mode |> Bitwise.band(0o777) == 0o600
```

Also assert that a pre-existing file is atomically replaced, the temporary file is absent after success, and normal process shutdown removes only the runtime file it owns.

- [ ] **Step 5: Run discovery tests and verify failure**

Run: `MIX_ENV=test mise exec -- mix test test/webby/runtime_discovery_test.exs`

Expected: FAIL because `Webby.RuntimeDiscovery` is undefined.

- [ ] **Step 6: Implement the supervised discovery publisher**

Implement `Webby.RuntimeDiscovery` as a GenServer. `init/1` creates the parent directory with `0o700`, encodes the fixed key set with Jason, writes `runtime.json.tmp.<unique>` using exclusive owner permissions, calls `File.rename/2`, and stores the exact path it owns. `terminate/2` removes that path only. `snapshot/0` returns the published map through `GenServer.call/2`.

The default metadata provider reads the configured scheme/host/port and `System.pid/0`. It reads the instance ID from `Path.join(Webby.Paths.config_dir(), "instance-id")`; if absent, it creates one UUID in an atomic owner-only file and reuses it on later starts. It must reject any host other than `127.0.0.1` in this version.

- [ ] **Step 7: Supervise runtime discovery after the endpoint is configured**

Add `{Webby.RuntimeDiscovery, []}` to `Webby.Application.children/0` after `Webby.Repo` and before `WebbyWeb.Endpoint`. Configure only the static listener contract:

```elixir
config :webby,
  listen_host: {127, 0, 0, 1},
  listen_port: 6477
```

Runtime identity must never be generated in compile-time configuration. `Webby.RuntimeDiscovery` owns the durable owner-only instance file described in Step 6, while tests inject a fixed metadata provider.

Run:

MIX_ENV=test mise exec -- mix test
