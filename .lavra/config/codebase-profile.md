# Codebase Profile

Generated by Lavra setup on 2026-08-27.

## Stack and Integrations

- Elixir 1.20.3 on OTP 29.0.5, pinned through Mise.
- Phoenix 1.8.11, LiveView 1.2.9, Phoenix HTML, Bandit, Ecto SQL, and SQLite.
- Tailwind CSS v4 and esbuild provide the Phoenix asset bundles.
- A dependency-light Chrome Manifest V3 extension uses ES modules, JSDoc, Node 22 tests, and TypeScript `checkJs` validation.
- Public application surfaces are the LiveView dashboard at `/`, JSON health at `/health`, authenticated Streamable HTTP MCP at `/mcp`, the `/browser` Phoenix socket, and `/live`.
- Runtime integrations are local by design. The scheduled upstream-contract checker uses Req to query GitHub, npm, and Chrome Status APIs.
- Release overlays support a macOS launchd agent and a Linux user systemd service.

## Architecture and Structure

- `lib/webby` contains domain contexts and runtime processes; `lib/webby_web` contains Phoenix transports and UI.
- `extension` contains the Chrome client, `priv/repo/migrations` owns SQLite history, `priv/contracts` pins protocol fixtures, and `rel` owns release assets.
- `Webby.Application` uses a `:rest_for_one` supervision tree covering telemetry, Repo, migrations, schema metadata, probe tasks, PubSub, live browser connections, the endpoint, runtime discovery, and cached runtime status.
- `Browsers` owns pairing, authentication, revocation, and scanning.
- `Discovery` sanitizes and routes browser observations and catalogs.
- `Pages` owns explicit registration and document-session lifecycle.
- `MCP.Credentials` owns hashed bearer tokens and scopes; `MCP.Broker` routes stable MCP actions.
- `Invocations` and `BrowserConnections` coordinate bounded asynchronous calls, cancellation, timeouts, and metadata-only audit records.
- The web layer depends on domain contexts. Schemas remain independent of web modules.
- Core invariants are loopback-only service exposure, explicit page registration, immutable browser-tab-document-catalog-revision identity, sanitized inputs, scoped credentials, bounded resources, cancellation propagation, and metadata-only auditing.

## Conventions and Testing

- Follow the repository `AGENTS.md` rules for Phoenix 1.8, LiveView, HEEx, Ecto, Elixir, Tailwind v4, and Req.
- `mix precommit` is the required completion gate and runs warnings-as-errors compilation, unused dependency checking, formatting, and ExUnit.
- CI additionally runs `mix credo --strict`.
- Extension verification is `npm ci --prefix extension`, `npm run typecheck --prefix extension`, and `npm test --prefix extension`.
- ExUnit uses Phoenix ConnCase, LiveViewTest, LazyHTML, and SQL sandboxing. Process tests use supervised processes and message/state synchronization instead of sleeps.
- UI tests target stable DOM IDs and outcomes instead of raw HTML strings.
- Reviews should emphasize authorization and origin boundaries, secret/file permissions, WebSocket and invocation races, cancellation, durable SQLite consistency, migration safety, payload bounds, and extension permission disclosure.
- The current dependency graph includes daisyUI even though current repository guidance forbids new daisyUI usage; distinguish pre-existing use from introduced changes and migrate carefully if removal is warranted.
