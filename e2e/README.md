# Webby live E2E contract

This package is the executable source of truth for Webby's live end-to-end coverage. It deliberately separates behavior from drivers: scenario JSON uses the closed `operation.op` and predicate `kind` vocabularies for logical handles, bounded waits, normalized outcomes, and cleanup. Unknown operations and predicate kinds are schema errors, so protocol and Chromium adapters cannot invent private semantics.

## Contract compatibility

The current contract version is `1`. Consumers must reject an unknown major version. Schema changes are atomic: update the schema, committed scenario and inventory snapshots, positive and negative contract tests, parity normalization, and every consumer together. Drivers may not privately reinterpret a scenario or omit a shared outcome.

Run the contract gate from this directory:

```bash
npm ci
npm run validate
npm test
```

Stable lane commands live in this package and are the only commands CI calls:

```bash
npm run ci:contract
npm run protocol:pr       # PR protocol, zero retries
npm run protocol:full     # main/nightly lifecycle
npm run chromium:smoke    # PR Chromium, one worker, zero retries
npm run chromium:full     # main/manual complete Chromium lifecycle
npm run mcp:compat        # pinned official MCP client
npm run replay -- artifacts/attested/sanitized-staging
npm run cleanup           # external reaper and final leak audit
```

The root `scripts/e2e` and Mix aliases only forward to these package commands;
they do not maintain a second scenario selection policy.

`npm run validate` prints the mapped/excluded denominator and fails when source extraction differs from the committed snapshot, the denominator implausibly shrinks, a surface lacks a scenario/reviewed exclusion, an extractor cannot understand its source, schemas fail, lifecycle assertions are incomplete, or timeout ordering is unsafe.

## Scenario selection

Each scenario declares a stable tier and integer weight. `deterministicShards` assigns the complete scenario inventory exactly once with deterministic weight balancing. Pairwise dimension coverage is required by default and is generated by `selectCombinations`; triple keys and values must be declared dimensions. `mandated_triples` are always selected. The protocol lane may expand a scenario's full Cartesian matrix; Chromium runs pairwise rows plus explicitly mandated triples unless a reviewed scenario exclusion says otherwise.

Adapter-specific scenarios are valid. A scenario whose `drivers` contains both `protocol` and `chromium` is shared, and both adapters must emit every normalized outcome with raw-observable provenance. Compare result files with:

```bash
npm run parity -- protocol-results.json chromium-results.json
```

Parity result files are validated by `support/parity-report.schema.json`. Every result declares its parity-critical raw-key denominator and reviewed raw exclusions. The gate fails if either adapter omits a shared scenario, an expected normalized outcome is absent, a required or unknown raw terminal observable is silently discarded, a raw value is projected into a different normalized value, or normalized values drift.

## Timing and cleanup

Fixed sleeps are forbidden. Every action waits on a named externally observable predicate with a finite budget. The hierarchy is strictly `action < step < scenario < shard < job < workflow`. Diagnostic recorder flush and cleanup use reserved grace inside the workflow budget. Cleanup assertions include processes, listeners, SQLite/WAL files, profiles, pending calls, and active sessions as applicable.

## Reviewed exclusions

Coverage exclusions are exceptional. They require the source symbol, owner, substantive rationale, approver, review date, and expiry. Security surfaces include harness capabilities, generated extension manifest fields, secret zones, and artifact types; they cannot be excluded implicitly.

The world manifest schema is the only launcher IPC contract. Standard output and error are diagnostic logs, never an API.
